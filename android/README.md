# Дневник — нативное Android-приложение

Нативное Android-приложение дневника: Java + системные виджеты + SQLite.
**Ноль разрешений**: в манифесте нет `uses-permission` — у приложения нет
доступа в сеть, а данные дневника не покидают папку приложения.

## Возможности

- Календарь месяца: статус дня цветной рамкой, часы учёбы, точка заметки,
  выделение сегодняшнего и выбранного дня (инверсия, как в веб-версии)
- Панель дня (диалог): учёба часы/минуты + сброс, таймер с живыми секундами
  (`Старт`/`Пауза`, `±5 с`, обнуление с сохранением накопленного),
  цель в день, четыре статуса, заметки (добавление, изменение, удаление,
  закрепление ★)
- Строка статистики: серия дней, часы за год, количество заметок
- Статистика года (по клику на месяц): почасовые итоги по месяцам, статусы
- Поиск по заметкам с переходом к дню
- 9 тем оформления (те же палитры, что в веб-версии)
- Экспорт JSON / текста в «Загрузки/Дневник» (MediaStore, без разрешений),
  импорт резервной копии JSON через системный выбор файла
- Очистка всех данных — только с подтверждением

## Как это устроено (и почему безопасно)

- Никакого WebView: интерфейс построен из системных виджетов
  (`TextView`, `GridView`, `Dialog`, `PopupMenu`) — приложение полностью
  нативное, оно устанавливается поверх веб-обёртки как обновление (тот же
  пакет, более высокий `versionCode`).
- Данные — только в SQLite приложения (`diary.db`), песочница Android.
- `allowBackup="false"` — данные не попадают в облачное резервное копирование.
- Экспорт — через `MediaStore.Downloads` в «Загрузки/Дневник», имя файла
  очищается от опасных символов.
- Импорт — через стандартный выбор файла (`ACTION_OPEN_DOCUMENT`), данные
  валидируются: ключи дат по регулярному выражению, минуты ограничены
  0…1440, статусы — белым списком, неизвестные темы отбрасываются.
- Тексты заметок выводятся через `setText` (аналог `textContent`) — разметка
  в заметках не исполняется.

## Сборка APK

Требуется JDK 17+ и Android SDK (`platforms;android-34`, `build-tools;34.0.0`):

```powershell
powershell -ExecutionPolicy Bypass -File android\build-native.ps1
```

Скрипт соберёт APK без Gradle (aapt2 → javac → d8 → zipalign → apksigner)
и подпишет его debug-ключом: `android/bin/study-diary.apk`.

Ключ подписи хранится в `android/debug.keystore` (вне `bin/`, который
чистится при каждой сборке, и в `.gitignore`). Это важно: при смене ключа
Android отказывается ставить обновление поверх установленной версии
(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`) — тогда приходится удалять приложение
вместе с данными. **Не удаляйте `debug.keystore`** — он гарантирует, что
будущие сборки встанут поверх текущей.

## Тесты

Логика и UI-потоки приложения покрыты автотестами (Robolectric 4.11 + JUnit4,
запуск — Maven, без эмулятора):

```powershell
& "$env:USERPROFILE\.tools\apache-maven-3.9.9\bin\mvn.cmd" -f android\tests\pom.xml test
```

(Можно любой Maven 3.9+ — подойдёт и `mvn` из PATH; первый запуск качает
зависимости из интернета, дальше работает кэш `~/.m2`.)

34 теста: календарь и навигация, панель дня (учёба, цели, статусы, заметки),
таймер (старт/пауза/продолжение, ±5 с, сохранение накопленного между
днями), поиск, темы, валидация и устойчивость SQLite-хранилища.

Тесты гонялись после каждой правки и нашли реальные баги v3.0 (клик по дню
не срабатывал, таймер терял время на паузе, сохранение при потере фокуса не
дожимало поля). Прогоните набор перед любым изменением исходников.

## Формат резервной копии

Экспорт JSON совместим с веб-версией: `notes` (по дням), `marks`
(минуты + статус), `settings` (цель, тема) — копию из браузера можно
импортировать в приложение и наоборот.

## Минимальная версия

Android 10 (API 29) — на более старых версиях MediaStore Downloads недоступен.

## Честные ограничения

- Подпись — debug-ключом (`android/debug.keystore`, в `.gitignore`),
  не ключом Google Play. Перед публикацией в магазине нужна release-подпись.
- v3.0 запускалась на реальном устройстве и оказалась сильно багированной
  (клик по дню не открывал панель, таймер портил отметки). Найденные баги
  исправлены в v3.1 и закреплены 34 автотестами, но эта среда не может
  запустить приложение на физическом устройстве — после установки v3.1
  проверьте базовые сценарии: открыть день, записать заметку, таймер.
- Ключ подписи v3.1 отличается от ключа распространённого v3.0 APK
  (см. «Важно про подпись» выше) — обновляться поверх v3.0 не получится:
  сначала удалите старое приложение (предварительно сделайте экспорт,
  если там есть нужные данные).
